# 会话变化后的监测与保存恢复

本修复包含在 0.3.0-rc5 候选版中；已发布的 RC4 附件保持不变。

## 已复现的根因

1. 应用使用时长将每个采样的 UTC 时间重新映射到单调时间轴。普通 5 ms 偏差即可使一分钟变成 60,005 ms，被原有 SQLite 约束拒绝。确定性测试先在旧代码失败，再验证单一连续段锚点修复。保留 60,000 ms 上限与 active ≤ foreground 约束，不截断错误数据冒充修复。
2. SQLite 保存、归档或其他 worker 异常会永久关闭用户要求的监测。用独立连接持有 BEGIN IMMEDIATE 实际复现；释放锁后旧代码仍不恢复。初始化数据库失败还会直接结束 worker。
3. 退出先停止线程，再询问是否取消。取消保存失败退出后，UI 还在，核心已经停止。
4. 最新输入快照会替换尚未交接的快照。长时间挂起后的缓存过期可能让未写入桶消失。水平滚轮净量回到零时，旧代码遗漏零值更新。
5. 网络暂停确认先于 ETW 缓冲排空。完整回归在真实流量下发现暂停后快照还会变化；隔离对照再次复现。现在返回暂停结果前结算已接受缓冲，开始前取得暂停基线；保留原始采集字节及质量定义。原暂停断言未删除，失败差异仅写入被忽略的测试目录。

旧诊断日志未记录 SQLite 原始码，不能把复现结果当作用户每一次历史故障的确切原因。实际用户库仅执行只读 quick_check 和版本检查，结果正常；主文件前后字节一致。未迁移、删除或重建。

## 保存链路

输入回调保持内存聚合；既有 1 Hz 快照将未交接桶交给 worker。worker 保留未提交的绝对计数，在配置的批量保存周期执行：

1. 聚合批次写入 data/pending/<session>.pending.tmp，FlushFileBuffers 后原子替换同会话的 .pending。仅保存现有聚合字段；不含输入内容、坐标、数据包或逐事件日志。
2. 一个 BEGIN IMMEDIATE / COMMIT 保存键鼠、网络、应用使用、排行及 session/revision 回执。
3. 只有主库 COMMIT 成功才更新内存确认状态、释放已保存旧桶并删除对应 pending。
4. 独立更新月度归档。归档失败保留主库记录并延后清理，后续从主库修复。

Schema v6 只新增 persistence_receipts；v5 升级前通过 SQLite Online Backup 创建一致性备份。旧版拒绝写入更高结构。清空统计时，事务内保留最高修订回执，避免残留快照恢复已清空数据。

重启按原 session/revision 重放 .pending，已提交或过期修订直接确认，不重复计数、不用旧快照降低新值。未完成的 .tmp 不重放；不可解析快照保留并显示恢复错误，不当作空数据。超过恢复大小限制时保留旧快照并报告。

BUSY/LOCKED、可恢复 I/O/打开错误先进行最多五次退避重试；持续环境错误转为低频恢复探测（60 秒），不高频循环。READONLY/FULL 不即时重试；校验/结构等非恢复错误保留现场，排除问题后主动重试。保持原用户监测开关。数据库尚不可用时，状态及控制仍可处理。

数据目录锁阻止不同登录会话或 EXE 副本同时写同一数据根目录；各模块仍使用统一绝对路径，不创建备用空库掩盖错误。

## 诊断与会话行为

- 状态返回数据库绝对路径、主码、扩展码、原始消息、未展开参数的 SQL 和事务阶段；保存错误写入 data/logs/storage.log（约 1 MiB 轮转）。目录本身不可写时状态保留错误，日志可能无法落盘。
- UI 区分保存、查询、归档、快照恢复及采集错误。详情可展开，提供“重试保存”。查询失败不覆盖上次成功结果为零；重复错误不反复重建提示。
- 锁屏/会话断开暂停输入与活跃统计，保留聚合及用户运行状态。网络锁屏策略保持原定义；休眠暂停采集，唤醒重建网卡差分基线，保留已有流量。
- 独立消息窗口注册会话通知，低频复核状态及 Raw Input 注册；缺失时才恢复，不创建第二个采集线程。
- 应用使用统计在既有定时器内低频重试初次失败的会话/前台通知注册，并复核会话状态；维护期间仍保留休眠门控。
- 退出先静止采集并保存；失败取消后继续原核心及补存。Windows 结束会话请求保存并作有限等待，不依赖关机最后一次保存保证日常可靠性。

可恢复：SQLite 已提交数据、可恢复的 WAL、已完整发布的聚合快照。
不可恢复：旧版已丢失的 RAM 数据、崩溃前尚未形成快照的尾部、主库和快照同时无法写入的数据。硬件故障也可能破坏文件；不承诺零丢失。

## 实际自动化验证

Windows 本机 LLVM-MinGW x64 Release / Debug 分别构建，完整 CTest 各 22/22。恢复测试 133 项、应用使用 62 项、前端存储故障 17 项；全部原有测试保留。

独立数据库覆盖：跨模块事务回滚；BUSY 后自动补存；VFS 注入 READONLY/FULL/IOERR_WRITE 后恢复；不执行 SQLite 清理的子进程异常终止；WAL/pending 重放；过期修订拒绝；重复重启；v5 原数据及备份版本；取消失败退出；输入交接；归档、恢复文件及 pending 目录不可用后修复。故障注入不填满真实磁盘、不修改用户权限。

会话测试只给本测试进程自己的 HWND 发送 WTS/电源消息，验证同一 session、采集窗口和两项 Raw Input 注册。它不能替代实际锁屏、休眠或重启。

另以隔离数据运行 Release 后台监测 75 秒，跨分钟保存、正常退出后 quick_check=ok，应用时长未超一分钟、active 未超过 foreground；这不是长期性能或事件准确率测试。归档路径故障下的真实 800×600 Settings 自检通过双语/双主题、托盘关闭、两次 WebView2 释放/重开及安全退出。用户原实例与数据未修改。

构建及完整测试：tools/build.ps1 -Toolchain PortableLLVM -Configuration Release（另以 Debug 重复）。

## 人工验收（尚未执行）

1. 备份后在独立 data 启动本轮 Release，主动开始监测，执行少量已知键鼠输入，等待一次保存；核对历史及保存时间。
2. 实际锁屏/解锁，再次输入并核对历史递增、未重复注册、活跃时长不含锁屏；检查存储状态。
3. 实际休眠/唤醒，核对采集恢复、网络不将休眠差额算作活动、使用时长不跳变。
4. 正常退出再启动，核对历史、默认启动策略及统一目录。只在测试目录做进程异常终止实验。
5. 经用户明确安排后真实 Windows 重启，核对 SQLite、月度归档和历史。此轮没有重启电脑。

真实高频事件丢失率、长时间运行、其他 Windows 版本、强制断电及磁盘硬件故障未验收。rc5 候选版按上述限制发布，用户部署前应确认备份及降级方案。
