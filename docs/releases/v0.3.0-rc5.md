# PulseTrace 0.3.0-rc5

Windows 10/11 x64 候选版 / Release candidate

## 更新 / Changes

- 修复锁屏、解锁或保存异常后监测可能停止的问题。采集线程在数据库和归档恢复后继续工作，失败退出被取消时不会遗留“界面仍打开但核心已停止”的状态。
- 聚合批次改为跨模块原子提交。保存失败时保留内存数据和待写快照；SQLite 恢复后自动补存，提交回执避免重试重复累计。旧版 v5 数据库升级前创建一致性备份，Schema v6 保留已有键鼠、应用使用、网络、月度归档和设置。
- 修复应用使用时长在时钟抖动下被错误拒绝、网络暂停后缓冲仍更新、会话通知首次注册失败后不重试、休眠跨越被错误计时等问题。
- 界面区分监测停止、数据库保存失败、历史查询失败及归档故障，并保留重试入口；查询失败不会显示虚假的零统计。

This candidate fixes monitoring stalls after lock, resume or storage errors. Aggregate batches now commit atomically across modules, failed saves retain pending data and retry without double counting, and schema-v6 upgrades create a consistent backup while preserving existing history and preferences.

It also fixes application-duration clock jitter, network buffers changing after pause acknowledgement, one-shot session-registration failures and suspend interval attribution. UI storage and query errors remain distinct and query failures do not render synthetic zero statistics.

## 数据与升级 / Data and upgrade

- 从 rc4 / Schema v5 升级时自动备份 `monitor.db`，然后事务迁移到 v6。新增内容仅为持久化提交回执表。
- 升级与普通卸载保留实际安装目录下的 `data`。新安装默认位置仍为 D:\Program Files (x86)\PulseTrace。
- 旧版程序不能直接写 Schema v6；降级必须恢复升级前备份或使用兼容版本。
- 升级前应完全退出旧程序。如果安装器提示保存失败，请先在旧程序中解决存储错误，安装器不会强制丢弃待写数据。

Upgrades from rc4 / schema v5 create a consistent database backup and migrate transactionally to v6. The migration adds only persistence receipts. Installs and normal uninstalls preserve the installation's `data` folder. Older binaries must not write schema v6; use the pre-upgrade backup or a compatible version when downgrading.

## 验证与限制 / Validation and limitations

- Release/Debug 构建及完整自动化回归在发布准备流程中执行；恢复测试覆盖 SQLite BUSY、只读、磁盘满、I/O 错误、异常终止后的快照重放、重复启动、v5 备份迁移、保存失败取消退出和网络暂停缓冲。
- 安装器生命周期测试使用独立测试 AppId 和隔离目录，不替换用户已有的正式安装。发布产物同时校验 SHA-256。
- 实际 Windows 锁屏、休眠、注销和重启仍属于人工验收项目。真实高频输入、长时间运行、其他 Windows 版本、物理流量独立抓包对照及任务栏第三方美化兼容性也需人工验证。
- 安装包未签名，可能触发 SmartScreen。程序需要 Microsoft Evergreen WebView2 Runtime；更新下载只提供校验后的手动安装。

Release and Debug builds plus the full automated regression run during release preparation. Controlled tests cover SQLite busy/read-only/full/I/O failures, crash replay, repeated restart, v5 backup migration, cancelled failed exits and network pause draining. Installer lifecycle tests use an isolated AppId so an existing registered installation is unchanged.

Actual Windows lock, sleep, logoff and reboot remain manual validation. The installer is unsigned and may trigger SmartScreen. Microsoft Evergreen WebView2 Runtime is required. IP and ranking observations retain their documented sampling and permission limits and are not billing totals.
