# 前端性能与 DPI 回归（2026-11-05）

在 `df93816` 的 Release 开发构建上先测量，再修改前端；C++ 监测与 SQLite 计量算法未改。环境沿用 [性能记录](performance.md) 的 Windows 11、Ryzen 5 5600/12 逻辑核、125% DPI。全部原始记录保存在忽略的 `build/perf-continuation`，不公开应用、路径、输入或网络历史。

## 保留的修改

- 数字格式化由每个数值创建一个 `Intl.NumberFormat` 改为两语言各复用一个；语言、舍入、无效值等输出保持原语义。Node v24.21.0 微基准每轮 20,000 次格式化、预热一次再测七轮，中位数 **504.27→15.73 ms**，结果校验和相同。复现：项目根目录执行 `node tools/benchmark-formatters.cjs`。这是格式化函数微基准，**不是整个应用加速 32 倍**。
- ResizeObserver 继续在浏览器布局周期处理尺寸变化，跳过未变尺寸的重复通知，取消已销毁页面的待执行帧；DPR 变化、恢复显示使用 RAF，隐藏时停止绘制。没有持续帧循环或固定 60 FPS 限制，不改变数据采样频率。数字图表、键盘布局和使用统计共享轻量观察器。
- 第一版将所有 ResizeObserver 回调延至下一 RAF，并监听全窗口 resize；交替与单项复测未验证收益，窗口 Private Bytes 较高，已撤回。最终方案仅保留必要的尺寸/DPR/可见性处理，不把该尝试计为成果。

## 原生进程实测

前后每种常态各运行 30 秒，取第 5–25 秒。使用相同配置、新数据目录、英文深色主题、30 秒写入周期，关闭更新与可选排行来源；后台监测包含新 AppUsageMonitor，不产生受控公网流量。CPU 按 12 逻辑核归一化；Private Bytes 为主进程、原生 helper 和所有观测到的 WebView2 子进程之和。此表使用最终轻量方案。

| 状态 | CPU 均值/峰值 %，前→后 | Private Bytes 均值 MiB，前→后 | 线程峰值，前→后 | 句柄峰值，前→后 |
| --- | --- | --- | --- | --- |
| 后台暂停 | 0.027/0.212 → 0.040/0.209 | 8.20 → 7.98 | 18→18 | 431→431 |
| 后台监测 | 0.027/0.214 → 0.047/0.208 | 8.25 → 8.41 | 19→19 | 437→437 |
| 主窗口打开 | 0.113/0.624 → 0.104/0.795 | 242.31 → 246.27 | 223→223 | 3672→3686 |
| 后台任务栏 | 0.076/0.429 → 0.048/0.415 | 9.25 → 9.60 | 21→20 | 496→477 |

窗口组主进程 Private Bytes **7.85→8.06 MiB**，WebView2 **232.68→236.42 MiB**；总 Working Set **428.85→431.31 MiB**。Working Set 会重复包含共享页，不能与 Private Bytes 相加。另行前/后交替两轮及单项试验显示明显启动/进程资源波动，不能从这些短测宣称整体 CPU 或内存下降。后台两组根本不加载修改的前端，CPU 差异也不能归因于这些前端修改。

窗口组进程 WriteTransferCount 增量 **613,483→709,595 B**，任务栏组 **106,940→75,302 B**，两个纯后台组在统计区间未观察到增量。该系统计数包含 IPC，**不是物理磁盘写入量**；30 秒刷新及退出写入也可能落在统计区间外，不宣称零磁盘 I/O 或磁盘优化。

另行真实窗口滚动/缩放生命周期自检：320 CSS px/36 帧滚动，RAF 间隔均值 **8.108→8.158 ms**、p95 **8.4→8.5 ms**，Sticky 与透明回退通过。这里是 JS RAF 时间间隔，不等于 GPU 呈现 FPS；生命周期交替显示/隐藏，不能将其瞬时内存或 CPU 当稳定窗口占用。全部测量实例正常退出，观测到的残留子进程为 0。

## 验证及边界

Release/Debug 构建；新增 40 项渲染生命周期、DPR 通知、隐藏/恢复、回收、双语格式缓存检查。已有 18 项 CTest 回归已执行，Release 原生自检遇到一次托盘不可用（同一时段 Explorer 重启），稳定后独立复测通过，失败日志保留；最终前端相关 8 项在 Release/Debug 再次通过。

DPR 单元检查是模拟通知，不代替真实多屏。当前桌面实际原生缩放/关闭/重开已测；其余刷新率、100/150/175/200% 实机、多屏拖动、GPU 帧时间、稳定生产页面切换延迟、长时间增长、输入硬件丢失率和独立网络准确性仍需外部条件。没有降低键鼠精度、关闭丢失检测或修改网络采集来换取资源数字。应用使用时长的受控前台权限限制见 [app-usage.md](app-usage.md)。
