# 验证方法与性能准入

所有指标区分聚合器重放、Windows 消息采集、真实 HID 硬件、端到端交互四个层次。重放零差异不能证明 Windows 输入队列不丢事件；没有设备报告不能视为采集准确性通过。测试不安装驱动、不启用 Hook、不调用 SendInput，也不修改输入设置。

## 自动计数与边界测试

```powershell
.\tools\build.ps1 -Toolchain PortableLLVM -Configuration Release
.\tools\build.ps1 -Toolchain PortableLLVM -Configuration Debug
```

`mouse_tests` 覆盖五键、重复 DOWN、缺失释放、系统双击超时边界、不重叠配对、跨分钟、设备隔离/重连、来源隔离、空句柄、状态表满、精密滚轮、short 最小负值、水平滚轮、分钟/小时/天、自定义半开范围、过期桶碰撞、时钟回退、32 位 tick 跨界及 300 万条样本流。

## 真实高频点击丢失率

使用现有的、能作为标准 HID 鼠标报告的独立硬件发生器，并独立记录发送报告/点击总量。没有发生器时只能做低速人工计数，不能给出高频丢失率结论。不要将 SendInput 结果拿来证明物理 Raw Input 能力。

1. 开始 `mouse_probe --capture --seconds 120`，静置 5 秒后发生器发送预定序列，结束前至少静置 5 秒供队列排空。测试期间不操作其他鼠标/触控板；保持桌面解锁。
2. 分别测试 125/500/1000 Hz，以及设备支持的 4000/8000 Hz 报告率。报告率不是点击率；按发生器能力分别生成快速 DOWN/UP 边沿，每个按钮至少 10000 次完整点击，重复三轮。
3. 将独立发生器汇总保存为与 `tests/fixtures/hardware-scenario.example.json` 同结构的 expected 文件，不包含坐标或逐事件日志。
4. 执行比较：

```powershell
.\tools\check-capture.ps1 -Report .\build\llvm-release\data\mouse-probe-实际编号.json -Expected .\build\llvm-release\data\hardware-expected.json
```

分别报告 missing / expected 与 extra；禁止正负误差相抵。准入目标为每轮已知序列计数完全一致、read/message 错误为 0、设备状态容量退化为 0。该结论仅适用于所测设备和负载。Windows 没有在本接口提供“所有可能丢失的硬件事件”的通用计数器，必须依赖独立发送总量。

## 连续滚轮准确性

发生器分别发送 `+120`、`-120`、`+15×8`、`-15×8`、交替 `+15/-15`、`+240`、零值和水平滚轮。每组至少一分钟，跨分钟/小时边界；尽可能加测真实高精度鼠标。检查：

- 正负事件数分别与非零垂直滚轮报告数一致；`+240` 是一个事件，不是两个。
- 正/负累计 delta 与发生器整数总量分别一致，净量和总量正确；没有逐事件截断。
- 水平滚轮不改变上下事件数；分钟、小时和自定义范围的汇总保持相同 delta。
- 触控板另测点击、双指滑动、惯性滚动和外接鼠标同时操作，记录未覆盖情况，不用空句柄直接断言触控板。

准入目标为各组计数和累计量完全一致；不能把“页面滚了几行”当作滚轮报告量真值。

## 鼠标操作延迟

`mouse_probe` 报告两个诊断指标：

- `callback_histogram` / mean / max：QPC 测量读取 Raw Input、解码、聚合和临时结构清零的处理时间。直方图边界是上界，最后一个槽为溢出；不是输入到应用的端到端延迟。
- `queue_delay_histogram`：当前 tick 与 `GetMessageTime()` 的差值。它使用毫秒级消息时间，仅反映本监测进程的消息队列延迟，不能解释为其他应用受到的延迟，也不能证明亚毫秒性能。

外部 A/B 测试使用 `mouse_latency_target`：每次窗口收到左键 DOWN 时翻转背景明暗，不读取坐标、记录时间线或注入输入。用机械/电气触发与光电传感器，或足够帧率的高速相机，同时观察按键触发和屏幕变化。监测关闭/开启随机交替，各采集至少 500 次，固定显示刷新率、系统负载、电源设置与设备；比较中位数和 p95 的增量，并报告测量分辨率和置信区间。

建议准入目标：端到端 p95 延迟增加不超过 1 ms，且测量分辨率足以支持该结论；若使用 240 fps 相机，单帧约 4.17 ms，不能据此宣称满足 1 ms 门槛。回调 p99 目标 < 100 μs、队列 p99 < 10 ms 作为待实测诊断目标，不当作当前承诺。

## 键鼠并发高频输入 CPU

```powershell
.\build\llvm-release\mouse_probe.exe --capture --seconds 120 --keyboard-count
```

在独立 HID 键盘和鼠标发生器同时输出已知序列时运行，与同等时长空闲、鼠标单独、键盘单独分别对照，至少三轮。键盘 sink 只累计 DOWN 数（包括系统/设备重复 DOWN），不保存键值或内容；它还不是生产 KeyboardMonitor，接入真实模块后必须再次测试。

`cpu_percent_one_core = 进程CPU秒 / 墙钟秒 × 100`，100% 表示一个逻辑核心满载；如换算整机平均占用需再除以逻辑处理器数。采集报告同时记录内存和按包回调分布。建议目标：空闲 < 0.5% 单核，1 kHz 鼠标加可实现的键盘高频报告 < 5% 单核；4/8 kHz 单列实测，不外推。空闲计时量化得到 0 不表示数学上的零开销。

## 内存与长期运行

```powershell
# 聚合器满速重放；会占满约一个核心，但不会操作系统输入
.\build\llvm-release\mouse_benchmark.exe --seconds 60

# 真实采集 24 小时；显式启用，Ctrl+C 可停止
.\build\llvm-release\mouse_probe.exe --capture --seconds 86400 --retention-minutes 1440 --keyboard-count
```

先进行 60 秒/30 分钟重放，再进行 24/72 小时实机采集。固定容量分钟环和设备状态表；重放报告每秒只保存资源聚合样本，真实采集在内存中维护资源统计并于停止后输出。比较预热后的 Private Bytes、Working Set、句柄与线程数，区分工作集变化和私有提交量增长。验证睡眠恢复、热插拔、设置变化、Ctrl+C、超时退出及无事件空闲。

建议目标：预热后 24 小时 Private Bytes 增长 < 5 MiB，72 小时无持续增长斜率；检测到持续增长应定位后复测。这是验收门槛，尚未完成本时长测试。分钟环老数据覆盖是验证程序既定保留策略，不算事件采集丢失，报告累计数仍覆盖本次会话。
